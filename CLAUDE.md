# CLAUDE.md

## What this project is

A client-side AI hashtag generator. Users paste text (articles, blog posts, captions) and get relevant hashtags generated entirely in their browser. No server, no API keys, no data leaves the device.

Three generation methods are available as tabs — users can compare results:

- **KeyBERT** — Sentence embeddings + cosine similarity + MMR diversification. Runs in a Web Worker via Transformers.js (WASM).
- **Chrome AI** — Chrome's built-in Gemini Nano via the `LanguageModel` Prompt API. Runs in a separate browser process.
- **WebLLM** — Llama-3.2-3B-Instruct via MLC's WebLLM library. Runs on the GPU via WebGPU.

## Running the project

```bash
npm install
npm run dev       # Start dev server
npm run build     # TypeScript check + production build
npm run preview   # Preview production build
```

No environment variables or API keys needed.

## Tech stack

- **TypeScript** — strict mode, no `any` where avoidable
- **Vite 8** — bundler and dev server
- **Tailwind CSS v4** — via `@tailwindcss/vite` plugin, styles loaded from `<link>` in `index.html` (not JS import) to prevent FOUC
- **Transformers.js** — runs `all-MiniLM-L6-v2` in a Web Worker for KeyBERT embeddings
- **@mlc-ai/web-llm** — runs Llama-3.2-3B-Instruct via WebGPU
- **web-vitals** — dev-only CWV monitoring

## Key architecture decisions

### Form HTML is inlined in index.html
The form is **not** generated by JavaScript. It lives directly in `index.html` so the page renders immediately without layout shift. `main.ts` queries existing DOM elements and attaches event listeners.

### CSS is loaded via `<link>` in `<head>`, not via JS
`style.css` is referenced as `<link rel="stylesheet" href="/src/style.css">` in the HTML head, not `import "./style.css"` in main.ts. This prevents flash of unstyled content (FOUC).

### All AI runs off the main thread
- KeyBERT: Web Worker (`src/worker.ts`) — communicates via `postMessage()`
- Chrome AI: runs in Chrome's isolated process — async Promise API
- WebLLM: GPU compute via WebGPU — async Promise API

### Common interface for generation methods
All methods implement `GenerationMethod` (defined in `src/types.ts`). This makes adding new methods straightforward — implement the interface and add it to the `methods` array in `main.ts`.

### Session persistence
User input (title, text), selected tab, and per-method results are saved to localStorage with a versioned schema and debounced writes. Restored on page load.

## Conventions

- No server-side code — everything runs in the browser
- Prefer editing existing files over creating new ones
- Form HTML lives in `index.html`, not generated by JS
- CSS classes use Tailwind utilities; custom theme colors are prefixed `buffer-` (defined in `style.css` `@theme` block)
- Methods communicate status via the `onStatus` callback (renders HTML into `#status`)
- The WebLLM system prompt uses few-shot examples with paragraph-length inputs — hashtags should be specific to the article's arguments, start with nouns/adjectives, and avoid broad topic words

## Prompt engineering notes (WebLLM)

The Llama-3.2-3B system prompt in `src/methods/webllm.ts` is carefully tuned:
- Asks for 8 hashtags (model sometimes produces fewer, `MAX_HASHTAGS=10` as ceiling)
- Explicit format instruction: "single line, spaces only, no numbering, no explanations"
- Good/bad examples to steer away from generic tags like `#productivity`
- Few-shot inputs are paragraph-length to match real article input
- `temperature: 0.3` for focused output, `max_tokens: 150` for headroom
